# 按模型配置文档识别（2026-11-12）

此记录替代 2026-11-11 的 DeepSeek 本地 PDF 文字提取方案。保留此前的新对话、协议地址提示和原生工具功能。

## 功能与设置

设置 → 模型提供商 → 编辑供应商 → 模型详情 → 文档识别（PDF OCR）。

每个模型独立保存开关、识别供应商 ID 和识别模型 ID，默认关闭。目标从已配置模型选择，不手填 ID，不复制 API Key；模型保存和供应商保存沿用现有确认流程，取消不保存。目标被删除、未配置凭据或与当前模型相同时明确报错。

开启后，当前上下文里的 PDF 和图片先交给识别模型转写，再将文字交回原模型回答。因此已知不能读取文件的模型也不会先收到一个被忽略的 PDF。普通文本和已提取文字的 Office 文档继续走原流程，未知二进制文件不会被作为乱码转写。

识别请求只包含固定转写说明和附件图像，不包含原模型的系统提示词、用户问题或整段聊天历史，不启用搜索与其他工具，也不递归进入另一个聊天服务。设置明确说明附件会发送至识别服务、并产生该服务的调用费用。

## PDF 与结果复用

- 移除 pdfbox-android 及其 BouncyCastle 传递依赖，不新增本地 OCR 库。
- PDF 使用现有 Android PdfRenderer 转为页面图像，逐页调用所选视觉模型，保留页码和顺序；不增加固定文件大小或页数上限。
- 图片直接交给识别模型，包括旧版图片文件内容块。
- 识别结果作为外部资料交给原模型，增加静态系统说明，避免将文档中的指令视作授权；这不能保证模型不会识别错误。
- 原附件保留。完整结果以内容 SHA-256、目标供应商/模型、协议、地址和转写提示词版本为键，保存在对应用户消息的 documentOcr 记录中。相同内容和目标复用结果，更换识别模型或附件内容会重新识别。
- 缓存只含识别正文和目标 ID，不含 API Key；属于私人会话数据，会随对话备份一起保留。
- 缓存更新在主线程进行，替换旧数组以避免后台准备线程与 UI 线程同时修改数组。按会话、消息 ID 和分支定位，不写入其他会话。
- 空结果、截断、拒绝、网络错误和取消都不会缓存整份不完整文档，也不会调用原模型盲答。
- 识别请求共用原生成任务的取消句柄，在后台工作线程等待网络回调；取消后不继续下一页。临时页面由现有生命周期清理。
- 未开启识别时，DeepSeek Flash 保留全页图像兼容输入；Pro 等文本模型的 PDF 会提示开启识别，不再本地提取文字层。普通模型的原 PDF 发送、一次图像兼容重试、预览与手动分享行为保留。

模型服务的视觉能力、输出和上下文限制仍然适用。文档识别不会使未知文件格式、损坏或加密文件自动变为可读取内容。
